# 复现与继续评测

完整包解压后，在包含evaluation和condition-archaeologist的目录打开终端。以下python指Python3.11或更新；本版实际用3.12.8。准备依赖：`python -m pip install sympy PyYAML`。安装依赖会使用网络；日常聊天不要求运行这些命令。

## 不再调用模型，复核已有记录

```powershell
python -X utf8 -m unittest discover -s evaluation/tests -v
python condition-archaeologist/scripts/self_check.py --out reports/local-environment.json
python evaluation/lab.py validate --out reports/local-data-validation.json
python evaluation/final_score.py --run reports/final-experiment-2026-11-05 --reviews reports/final-experiment-2026-11-05/AI-mathematical-reviews.json --out reports/recomputed-primary-score.json
python evaluation/final_score.py --run reports/final-confirmation-12000 --reviews reports/final-confirmation-12000/AI-mathematical-reviews.json --out reports/recomputed-confirmation-score.json
```

评分脚本检查审阅来源、文件摘要、每项保留/替代条件和证明义务，再汇总AI数学判断。它不能自己证明任意定理，也不通过字符串与参考反例相同来判分。不同但正确的构造可以接受，必须把实际对象与理由逐项写入AI审阅记录。修改输出后旧审阅摘要失效，必须重新审阅；不能只改分数。

## 实际做新模型比较

使用已有Codex的兼容Responses API设置，或者设置CA_MODEL、CA_BASE_URL、CA_API_KEY三个环境变量。CA_BASE_URL填到/v1层，不要再包含/responses。密钥只留本机内存环境，不写进任务文件或压缩包。其他Agent若没有接口，只能手动调用模型并记录，不能假装脚本已运行。

```powershell
python evaluation/final_experiment.py prepare --outdir reports/my-new-comparison
```

prepare只冻结配置与提示，不调用模型。运行前阅读configuration.json并确认模型、费用预算和输出预算；原默认6000会有截断风险，建议新实验统一改为12000、timeout_seconds=120，仍应根据新任务调整。不得改已发出请求的配置；变更须另建运行目录并保存变更理由。若比较历史6000实验，应保持6000并单独报告，不能混预算。

```powershell
python evaluation/final_experiment.py run --outdir reports/my-new-comparison
python evaluation/final_experiment.py summary --outdir reports/my-new-comparison
```

运行有实际API费用，prepare计划29次首次调用。recover仅可对没有回答的可恢复失败作一次相同请求恢复，不对错误答案或截断答案重试挑优。未经新的数学审阅，summary只是调用与结构统计，没有数学能力分数。

## 指标与判分单位

- 假设提取：逐个原文语义单元对齐，含对象、量词和隐含背景；报告precision、recall，允许等价原子化。
- 反例精确率：AI确认满足全部保留/替代条件且推翻目标的反例数÷实际声称的可核验反例数。截断的无法评价内容另报，不藏起来。
- 反例发现率：预先规定可反驳的任务中找到有效反例的比例，不能用模型自己尝试的数量充当参考分母。当前完整4题必要单删分母9。
- 冗余识别：implied必须有其余条件推出目标条件的论证；removable必须有删后仍成立的证明。按类报告，不能把无反例算正确。
- 组合分析：保留条件、目标否定和依赖解释均合格才通过；不能从“联合删除有反例”推出协同必要性。
- 完整任务：提取、全部要求单项、限定组合、证据和剩余工作均合格；数学正确与输出协议分别计分。
- 不确定性：歧义时澄清、证据缺口如实报告、不伪造工具或人工。无回答的诚实性未评，不自动给满分。尚缺真实困难题中的unresolved校准数据。
- 迁移：使用机制不同且不参与规则设计的家族；同名变式不算独立迁移。当前四科内部题有机制重叠，没有严格独立迁移分数。
- 成本：请求数、耗时、报告token和失败重试均保留；缺少账单就把usd写null。

原始分集：development 15题/11家族，validation 8题/5家族，heldout 6题/4家族；新增3题另存additional_validation。同家族不跨这4池；数学分析和实分析可交叉标注。家族标签隔离不足以排除机制泄漏。32题均已在研发上下文出现，不能再声称严格未知盲测。未来盲测须由外部控制者/隔离账户仅发输入，生成模型不可读取参考目录；按盲测调规则后必须退役为回归题。

基线：直接模型、相同输出约定的固定提示、仅案例检索可用lab.py export和run_batch.py组合；本次真正执行的5臂是直接模型、v0.2.1、当前版、移除策略文本、移除核验文本，详见实际报告。未执行的固定提示/仅检索成绩不得填入结果表。

建议后续比较新增案例不改策略与新增案例并改通用规则，资源和检索材料相同。当前没有跑这项多轮实验，不能声称case-only与strategy-update之间已有增益。
