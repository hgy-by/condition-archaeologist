# 架构与证据说明

主运行源码只有一份：skill/。网页保留可独立分发的web/skill副本；工程检查逐文件比较两者，不一致即失败。安装到客户端属于第三个副本，需要显式安装，不会由修改网页自动覆盖。

网页流程：输入完整定理和科目 → 服务端加载Skill、判定协议、策略、验证说明与输出规范 → 一次模型请求 → 本地结构和核验义务覆盖检查 → 显示报告。开发种子、评测参考答案与用户令牌不进入数学提示词。网页当前不执行模型请求的代码、独立审阅或形式化证明。

本地校验能发现编号不一致、遗漏保留条件核对、伪造证据类型、无来源依赖边和不完整输出，但不能判断每一段数学论证是否成立。覆盖统计只针对模型已提取的假设，不证明提取完整。

四种状态独立记录：

1. 文件已生成：存在可读取内容。
2. 工程检查通过：相应脚本的真实运行结果与日志。
3. 真实调用成功：真实服务有返回且通过本地格式检查；仍不等于数学正确。
4. 数学复核通过：审阅者逐条检查对象、保留/替代条件、被删条件、结论、证明和不确定性，并注明AI或人工身份。

历史32个参考任务的用户确认仍是概括性确认：原29题通过且无改动，新增3题通过。没有新增伪造的人类逐题审核表。历史AI审阅和原始模型输出可追溯，但不转作当前ChatECNU模型的成绩。

历史开发/验证/留出案例及答案都在完整项目内；这种公开分发只能提供固定回归，不能保证之后仍是严格盲测。严格盲测应由外部控制者保管新题与答案、隔离执行者访问、冻结模型与预算，并在解封前保存输出。按留出答案调参后，该批次只能作为旧回归。

未证明：任意数学学科覆盖、任意定理反例搜索完备性、形式化可靠性、新模型泛化能力、本维护版RSI收益。人工确认或AI复核也不等同于形式化证明。
