# 提交前检查

本地实现与自动检查由AI继续处理；以下事项需要真实项目成员决定或实际操作。

GitHub作业提交的逐步操作见[GitHub提交步骤](GitHub提交步骤.md)，截止日为11月30日。

## 当前必须由人决定

- 确认老师要求的提交形式、评分要求，以及是否明确要求独立人工数学审阅。若老师要求，AI审核不能代替。
- README署名已确认为侯冠伊、徐炳涵；仓库计划公开；本次不提交最终海报，也暂不添加开源许可证。
- 如果运行真实模型测试，确认学校API预算，在本机启动窗口输入令牌；不要把令牌发给Agent。当前尚未取得本轮次数授权。
- 打开新版网页，确认真实浏览器中的展示与交互。当前自动检查不包含真实浏览器截图验收。最终海报以用户提供的 A2 PDF 为准，本项目旧 A3 文件仅是维护草稿。
- GitHub仓库尚未创建或推送；提交候选已准备不等于远程已发布。

## AI可完成，只有无法消解的关键问题再升级

- 代码、文档、导出、检查、迁移和版本一致性修正。
- 按数学清单逐项复核新输出；记录AI身份和具体理由，计算可验证部分另行记录。
- 对结果计算指标、基线/消融比较和RSI门槛；没有输出或审阅数据时留空。
- 核对来源具体定理段落、建立新题池和失败记录；无法明确教材定义或原命题含义时请用户确认。

不需要重新人工核验所有旧题。需要人处理的具体疑问须登记在reports/current/review-register.json；普通实现或明确初等数学可以由AI继续复核。公开发包后仍需在队友电脑上完成一次解压、启动示例、输入本机令牌和一条真实分析的验收。

## 发布操作顺序

1. 阅读当前检查与未完成事项，不照搬历史成绩。
2. 运行scripts/check_project.py，比较skill与web/skill，制作清单并检查归档。
3. 在第二台电脑按README解压启动，保存实际验收记录。
4. 创建公开仓库并按GitHub提交步骤上传；本次不加入海报。向老师确认是否还有超出已知要求的其他材料。
5. 若仓库公开，确认没有真实令牌、个人未公开材料和未授权内容；完整回归答案公开后不再称严格盲测。
6. 获得最终发布指令后再上传；保存版本和可恢复备份。

局域网短期试用与异地固定网址是两种部署任务。公网服务另需主机、域名/HTTPS、持久化额度及运维安排，不是本地压缩包可自动完成的事项。
