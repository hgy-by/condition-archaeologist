# RSI 更新协议

首版是可改进的策略与流程系统；没有修改模型权重。不把手工修补或案例积累单独称作已证实的递归自改进。

用户要求更新时：冻结当前版本及哈希→收集开发案例失败轨迹→独立数学审阅→提出可迁移候选规则→在临时副本修改→固定模型/权限/预算做配对回归→验证集筛选→按所选评测模式记录接纳决定（AI内部维护或正式独立审阅）→保存旧版以便回滚。正式研究的独立审阅门槛见下文，不因维护发布而降低。

每次记录 source_case_ids、failure_class、proposed_change、expected_effect、regression_risk、baseline/candidate 配置、实际结果、reviewer、decision。source_case_ids 必须来自已审阅开发集。无数据时状态 pending，不能自动接纳。

研发包的 lab.py gate 检查验证集证据、同任务与配置、可靠性、改善幅度及家族配对区间；通过只表示进入人工接纳环节。新增案例先入待审池，不自动变成金标准。

隔离比较：相同新增案例和资源下，比较只增加检索与检索加通用策略更新；用不同定理家族检查迁移。至少两轮有实际结果才能讨论多轮改进。开发回归/验证集不能读取盲测答案；根据盲测调参后该批次只能作为旧回归集。盲测由外部控制者提供输入并保存输出，严格盲测须另账户/容器隔离文件访问。

## AI复核工作模式（用户已选择）

可按同一核验清单由AI复核，逐条保存保留条件、替代条件、结论否定、依赖和不确定性；记录reviewer_type=ai、实际审阅者和证据摘要。不能填写伪造的人类身份或宣称独立人工通过。

AI结果可用于候选修订、工程回归、日常辅助版发布与内部比较，不必再要求用户审核每份回答。发布维护版本不代表通过RSI收益门槛。原lab.py的正式独立评测门槛保留；AI分数使用ai_reviewed_internal，不能自动转换为reviewed_score。正式研究结论可另行补充独立评测，而不是日常使用的前置许可。

新旧版本应在未用于拟定候选规则的隔离任务上做相同资源的配对实验。直接模型与Skill的比较不能代替旧Skill与新Skill的RSI比较。若置信区间含零、任务太少或只完成软件回归，报告“尚未证明改进”，保留旧版并支持回滚。
